# 研究内容展开与中文论文表达

版本：writing-guide-2，2026-09-21。与 internal-v3.1 评分量表配套；本文件用于生成正文，评分报告用于验收。优先级服从题面和适用赛事规则。

## 先形成可写的研究内容

写作前依次读取本文件、`docs/PAPER_QUALITY_STANDARD.md`、对应建模报告、结果及图表。写作计划记录实际读取路径、版本和各节证据位置。主会话直接写作也执行这些步骤。原生入口不会自动执行上游 Python writer 提示词。

每问先建立“研究问题—具体困难—模型关系—求解过程—结果比较—解释”的章节骨架，再写连续段落。给每一小节标明：要回答的问题、已有的公式或结果、支撑图表、尚需获得的分析。内容不足时补做相应推导、算例或统计，再交写作；用真实研究支撑初稿的充实程度。

一个有内容的算法章节通常包含以下相互衔接的单元，按本题需要取舍：

| 单元 | 读者读完后获得什么 | 适合提供的材料 |
|---|---|---|
| 对象与困难 | 数据结构、规模差异、导致优化困难的具体关系 | 六算例特征表、局部依赖图、容量与需求对照 |
| 方法选择 | 该方法如何利用上述结构，备选方法的差异 | 针对本题的比较，而非通用算法介绍 |
| 数学构造 | 从变量、集合和定义逐步得到目标、约束与性质 | 关键等式的推导、约束解释、条件与证明 |
| 求解展开 | 输入经何种状态更新成为输出 | 伪代码、参数来源、平局规则、停止条件、复杂度 |
| 局部示例 | 一次决策如何改变驻留、地址或流水 | 可手算小例、前后状态表、局部时间轴 |
| 实验设计 | 比较对象、控制条件、评价量为何适合本问 | 实验设置、共同预算、基线和评价量定义 |
| 结果与解释 | 数值差异出现在哪里，与哪些可观察过程相对应 | 汇总结果、动态过程、分组比较、必要的消融 |
| 小结与衔接 | 本问回答了什么，哪些输出进入下一问 | 含实际结果的局部结论 |

### 篇幅在内容计划中落实

在写作计划中分别记录有效正文页段、正文汉字量、模型/求解/分析占用情况，封面、目录、摘要、参考文献和附录另列。章节比例辅助发现失衡；上游 writer 建议的模型建立与求解占主体，可作为起点，再按赛题调整。

NPU 2025 A 当前 17 页稿的正文约 9,456 个汉字、跨 14 页；四篇同题样本的具体边界见研究报告。此次修订以 **约 1.6万—2.2万正文汉字、约 26—34 页有效正文**作为内容策划范围（当前阅读版版式下的估计，非官方要求、评分阈值或完成承诺）。实际页数由有效图表与版式决定。新增内容集中在三问的求解细节、过程解释与算例比较，完成后据实调整范围。若低于计划，逐项解释哪个论证单元已充分覆盖、哪个分析仍缺；不能以一句“短但完整”跳过用户明确指出的内容不足。

## 段落如何展开

方法段从具体困难引出定义，解释关系，再说明求解操作。公式前有建模动机，公式后解释符号及约束作用；关键变换交代成立条件。结果段先给比较条件和观察量，再给差异、具体阶段及解释。解释强度随证据确定：轨迹支持过程描述；控制实验或证明支持更强归因；尚待检验的解释写为明确假说并安排验证。

研究问题融入图前正常论述；图中呈现能回答它的量。图件顶部和底部保持干净，图题、分面说明与必要条件统一写入图下的 TeX caption；随后用正常正文解释主要现象、差异及对本问答案的影响。不同图承担不同作用，例如六算例概览、代表性局部放大、动态演化与优化前后对照。时间轴比较共用尺度，图例、配色和符号跨图一致。详细曲线应有可读的局部视图；正文解释这些局部与整体指标的关系。绘图和嵌图均全文读取 `docs/FIGURES_ZH.md`。

段落功能可以分布在相邻数段，不规定每段固定句数，也不强制每图机械写三行。过渡从前一段的研究发现引出下一步。例如，容量汇总显示压力集中于某类缓存，下一段自然转入该缓存的驻留过程。只有实际数据确认压力集中时才采用该论断。

## 用条件和对象表达范围

句子的主体优先是缓冲区、调度序列、执行单元、算法、参数或观察结果。将适用条件放在结论所在句，随后直接说明所得结果。具体改写见 `docs/paper-quality/positive-language-examples.jsonl`，条目标记为本项目原创功能示例；带占位内容的条目需补真实证据。

“只……不……”“不是……而是……”“不能据此……”“不构成……”进入人工语义检查，结合上下文判断：

- 数学约束、反证、必要反例、零结果和真正的方法差别保留。例如“同一执行单元上的操作不能重叠”具有明确数学意义。
- 若句子主要预防读者误解，改成准确的对象、定义、比较基准或条件。例如将“不能称为全局最优”落实为“在固定驻留关系下，……”。
- 同一限制在方法定义处交代，结论沿用该范围；模型评价集中讨论其研究影响。摘要、图注、表后、结论逐处重复免责会挤掉研究解释。

审计信息安放在适合的材料中：工具版本核验状态、人工复核进度、内部评分、哈希、执行日志进入项目报告或 AI 使用记录；正文承载模型、方法、结果和必要科学边界。赛事要求进入提交物的 AI 声明按当年规则保留，真实披露参与范围、工具信息和责任；未知必填信息如实标注并待核实，不虚构已完成的人工审核，也不以修辞优化隐藏必须披露的事实。

## 初稿的完成形态

### 正向论述与本轮语言要求

本节为用户针对当前论文系列明确指定的文风，不声称所有学术论文都使用这一规则。研究叙述围绕困难、结构发现、方法设计、可观察变化、比较结果依次展开。算法优势表现为对具体困难的处理和同条件下的实际收益；直接给出对象、动作、数值与适用范围。

1. 成品全文的可见自然语言使用零引号，包括标题、摘要、正文、图表、注释、参考文献及作者编写的附录叙述。术语直接定义，强调靠句义，文献用间接转述并正常引用。扫描中文单双引号、英文成对引号、直角引号、TeX 成对反引号或引号命令；逐页确认渲染结果。源码字符串定界符、原样代码附件、数学导数撇号、角秒符号不是修辞引号，保持其语义；原始题面与官方文件也保持原样。此要求不扩张到内部审计报告和代码语法。
2. 逐处改写把字句，尤其把……化、把……转化为、把……显式化。用明确动词和关系，例如节点顺序决定驻留区间，地址复用形成等待依赖。避免仅把字替换成将字后继续空泛地声称实现了某种化。具体建立了什么变量、约束或递推，直接写出来。
3. 不应、不把、不按、并非、没有、不能据此、不是……而是等先作语义定位。补充性否定若只用于预防误解，删去尾部辩解，将比较条件或研究对象融入主句。逐节交付完整修订句，不能用保留科学边界为理由原样放过本轮已指出的防御性句子。
4. 科学事实仍完整：约束、反证、零结果、负相关和实质局限均准确保留，能正向表达时优先表达。例如同一执行单元按顺序执行各操作；在已测试区间，指标保持恒定。局限集中在模型评价，用对象、适用域和具体代价表达；方法定义处保留必需条件，避免摘要、图注、表后和结论重复免责。
5. 算法高效必须有复杂度或耗时证据；搜索域固定可直接描述固定了哪些变量、优化哪些变量。取消否定句不能扩大适用域，故事性不能替代基线、推导和实际数据。

本轮精确反例的合格改写：

- 六个计算图采用统一的候选规则和参数设置。该句准确交代共同设置，无需追加按算子名称特判的否定。
- 该策略沿既定地址链构造可行顺序，搜索范围为固定驻留图上的指令重排，计算开销由上述路径计算、队列维护和依赖构造三部分组成。该句保留搜索域，并让效率依据回接复杂度。
- 本文依次优化节点顺序、连续地址分配和流水调度，分别降低驻留峰值、额外搬运量和完成时间。采用此句前逐项核对实际比较结果；若某指标未下降，应写实际观察。

语言审读记录扫描范围、源行/PDF页码、原句、修订句和保留语义。引号零出现可核验；把字句与否定句数量用于定位，评分根据实际表达缺陷。任何未处理的修辞引号均使本项目语言要求未完成。全篇系统性防御表达须整稿返修，不能仅记录 WARN 后宣布可交付。

初稿提交给用户前，作者完成一次内容审读和一次语言审读。内容审读逐节确认上述论证单元有实际内容、图表有分析、主要结果有针对性比较。语言审读把审计话术移到适合位置，减少重复限制，将泛泛评价改为具体观察。局部措辞可留待润色，结构缺项与尚未执行的核心分析在进入完整初稿前处理。

验收使用 internal-v3.1 原有 D/E/F 子项：论证单元缺失体现于结构与逻辑；防御性套话、抽象把字句及研究对象缺位体现于学术语言；图表缺少研究问题或解释体现于图表组织。页数与句式命中次数作诊断证据，评分仍需语义判断。保留评审报告中的真实问题，修正文中表达位置与内容组织。
