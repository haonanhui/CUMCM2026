# Stage 02 — 方法检索（Retrieve）

输入：题目分析报告.md（每问四要素 + 题型标签）。
目标：给每问 2-4 个候选方法，标注数据需求、复杂度、先例频率（饱和程度）。
出口条件（G2）：候选方法表落盘，每问主推 ≥1、备选 ≥2。

## 检索顺序（逐层扩大）

1. **本地中文算法库**（第一优先，快）：
   读 `code/vendor/math-modeling-skills/references/problem-algorithm-map.json`，
   按题型关键词（优化/预测/评价/分类/图论…）命中 primary/alternative 组合；
   细则查 `references/algorithm-library/0N-*.md`（7 类：优化/预测/评价/图论/统计/综合/ML）。
2. **HMML 方法树**（英文，补机理与经典模型）：
   读 `code/vendor/LLM-MM-Agent-hmml/HMML.json`（5 大类 → 子域 → 叶子方法），
   把题目领域词（如 VLSI 布局→floorplanning→组合优化）映射到方法节点；
   注意其 leaf 节点 description 带 modeling_method/core_idea/application 三段，直接可引用。
3. **2018 优秀论文对照**（对手盘）：
   在 `2018年优秀论文/` 里 grep 同题型题目（如 B 题物理仿真/优化），统计获奖论文用了什么方法组合，
   目的有二：方法被高频使用 → 标"饱和"（撞车风险）；写法惯例 → 留到 05 用。
4. **在线检索**（耗时可控时）：
   WebSearch 当年/近两年同类问题的 SOTA 方法（英文关键词优先），评估是否有更新更好的方法可引入；
   记录来源 URL。禁止搜"XX题 题解"类照抄内容。

## 产出：候选方法表（`02_retrieve/candidates.md`）

每问一张表，列：候选方法 / 类型标签 / 适用依据 / 数据需求 / 复杂度与规模上限 /
先例频率（高=烂大街 中 低）/ 潜在新颖性杠杆 / 来源（本地库条目或 URL）。

## 纪律

- 先例频率是后面 novelty gate 的输入：诚实标注，不因为想用某方法就压频率。
- 方法名统一：中文名 + 英文缩写（如 模拟退火 SA），保证论文与代码一致。
- 若某问只能找到"标准方法"，在表里直接写明：此问创新点将来自建模角度而非算法角度。
