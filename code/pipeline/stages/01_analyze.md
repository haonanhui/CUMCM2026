# Stage 01 — 分析拆题（Analyze + Triage）

输入：`00_ingest/problem.md` + manifest.json。
目标：把开放性赛题变成可建模的数学问题集合；若多题可选，辅助选题。
出口条件（G1）：题目分析报告.md 完成；每问有目标/约束/数据/输出四要素。

## 执行步骤

1. **逐问拆解**：对题目的每个小问输出四要素：
   - 目标（要回答什么/优化什么）
   - 约束与假设（显式规则、隐式物理/工程约束）
   - 可用数据（对应附件表、字段清单）
   - 期望输出（表格、曲线、方案、指标值）
2. **题型映射**：读 `code/vendor/math-modeling-skills/references/problem-taxonomy.md`，给每问打类型标签：
   优化类 / 预测类 / 评价类 / 图论网络类 / 统计类 / 机理-仿真类 / 机器学习类 / 综合。
3. **选题评估**（若 A/B/C 多题可选）：读 `code/vendor/math-modeling-skills/references/problem-triage.md`
   按六维打分：数据可得性 / 机理可建模性 / 方法新颖空间 / 求解复杂度 / 论文叙事张力 / 队友能力匹配。
   输出对比表 + 推荐排序。
4. **数据预检**：对每张附件表做 `head` 级检查（列名、缺失率、量纲、单位换算需求），标出"需要清洗/需要领域假设"的点。可复用 `code/vendor/math-modeling-skills/scripts/check_data.py`。
5. 产出 `data/contest/<contest>/<题号>/01_analyze/题目分析报告.md`，结构：
   - 题目背景摘要（2-3 句）
   - 每问四要素表 + 题型标签
   - 关键难点与风险（数据缺失/机理不明/规模爆炸）
   - 待真人拍板的问题清单（如选题）
6. **停点**：若存在选题，把推荐序交给真人确认后才进入 02。

## 写作纪律

- 分析报告是给队友+后续 agent 看的施工图：只写事实与推理，不写套话。
- 引用题目原文处标 `[原题]`；引用 2018 优秀论文惯例处标 `[2018-<题号>]` 并写文件名。
