# Stage 06 — 审计与提交（Audit + Submit）

输入：编译好的 PDF + frozen_numbers.json + 复现清单.json + 全部阶段产物。
目标：交付前最后一道闸：一致性、完整性、合规性、提交包。
出口条件（G6）：审计报告全项 PASS；提交包内容与命名合规。
**停点**：最终提交必须真人执行。

## 审计三件套（对应 vendor G6 三审计员，产出落 `06_audit/`）

1. **一致性审计**（`cross_media_consistency_audit.md`）：
   - 论文中每个数字 ∈ frozen_numbers.json（跑 `lib/frozen_numbers.py check --tex ...`）
   - 图表数量与正文引用一致（每个 figure/table 至少被 \ref 一次）
   - 摘要里的方法名与第 5 节模型名一致
2. **完整性审计**（`completeness_audit.md`）：
   - 七段结构齐全（问题重述/分析/假设/符号/模型/评价/参考文献）
   - 每问有：模型公式 + 求解算法 + 结果图表 + 结果分析四要素
   - 参考文献 ≥10 且方法原始文献在列
   - 附录含完整代码，代码与 `code/solve/` 一致（diff）
3. **质量审计**（`qa_report.md`）：
   - 摘要 ≤1 页、无元写作/报告腔/工程术语
   - 每条假设有依据、每个结论有证据或标注假设来源
   - 敏感性分析结果已写入模型评价节
   - 查重自查：连续 13 字与公开来源重合的段落改写（赛题原文引用除外）

## 提交包

1. **AI 使用报告**（2025 起多数赛事要求，如实填写）：
   - 使用了哪些 AI 工具、各自用途（分析/检索/代码/写作）
   - 人工审阅与修改比例、关键决策（选题/模型路线/定稿）由谁拍板
   - 本流水线的三处真人停点记录即证据
2. **命名与打包**：按官方提交说明核对（华数杯规范 PDF / 国赛当年通知）：
   - 文件名格式、PDF 大小上限、是否需承诺书扫描件
   - 打包为 zip 前用 `python -m zipfile -l` 复查内容清单
3. **冻结最终态**：提交后把 `paper/`、`data/contest/<contest>/`、`code/solve/` 打 tag 或复制到
   `data/contest/<contest>/_submitted_snapshot/`，防止赛后误改。

## 审计报告格式（`06_audit/audit_report.md`）

```markdown
# 提交前审计 — <contest> <题号> <日期>
## 一致性：PASS/WARN/FAIL + 证据
## 完整性：PASS/WARN/FAIL + 证据
## 质量：PASS/WARN/FAIL + 证据
## 遗留风险：<明确列出，不藏>
## 结论：可提交 / 需修复后复审
```

## 纪律

- 审计发现问题 → 修复 → 重跑对应审计项，不留"口头已修"。
- 任何 UNVERIFIED 结论在提交前要么补验证，要么从论文中删除。
- **提交动作本身由真人执行**，agent 只准备提交包与核对清单。
